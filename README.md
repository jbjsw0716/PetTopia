# README

# 펫토피아 (pettopia)

반려동물 용품을 둘러보고 장바구니에 담아 주문하고, 펫시터를 찾아 돌봄을 예약하는 리액트 펫샵입니다.

## 서비스 소개

- **이름** — 펫토피아(영문 `pettopia`). 수업(리액트) 팀 과제로 만들었습니다.
- **목적** — 상품 탐색 → 장바구니 → 주문 → 주문 내역, 펫시터 탐색 → 예약 → 예약 내역이 한 사이트에서 이어지는 흐름을 리액트로 구현합니다.
- **대상 사용자** — 강아지·고양이 보호자. 사료·간식·용품을 동물과 종류별로 비교해 사려는 사람, 출장·여행으로 아이를 맡길 펫시터를 찾는 사람입니다.

## 배포 주소

[https://pettopia.pages.dev](https://pettopia.pages.dev/)

## 실행 방법

필요한 환경은 Node.js **20.19 이상**(22 계열은 22.12 이상)입니다. 팀에서 확인한 버전은 24.19.0 입니다.
명령은 이 폴더(`pettopia/`)에서 칩니다.

```bash
npm ci
npm run dev
```

`npm ci` 는 `package-lock.json` 그대로 의존성을 설치합니다. 개발 서버는 [http://localhost:5173](http://localhost:5173/) 에서 열립니다.

배포 전에는 코드를 검사하고 빌드 결과를 미리 봅니다.

```bash
npm run lint
npm run build
npm run preview
```

- `npm run lint` — oxlint 코드 검사. 경고·오류 0 이 기준이고, 0건이면 명령 이름 두 줄만 나오고 끝납니다.
- `npm run build` — `dist/` 에 빌드합니다.
- `npm run preview` — 빌드 결과를 [http://localhost:4173](http://localhost:4173/) 에서 엽니다. 그 포트를 다른 서버가 쓰고 있으면 다음 빈 포트로 열리니 터미널에 찍힌 주소를 씁니다.

데이터·계산 테스트(3개 파일 10건)는 따옴표로 감싼 파일 패턴으로 실행합니다(`node --test tests/` 처럼 폴더만 주면 Node 24 에서 실패합니다).

```bash
node --test "tests/*.test.js"
```

## 사용 방법

### 상품 주문

1. 헤더의 **DOG**·**CAT** 이나 홈의 분류별 목록으로 상품 목록에 들어갑니다. 헤더 돋보기를 누르면 검색 창과 인기 검색어가 열립니다.
2. 상품 목록에서 검색어·동물·분류·정렬로 좁힙니다. 검색어는 상품명·분류 이름·동물 이름에서 찾고, 띄어 쓴 낱말이 모두 들어 있어야 찾습니다(예: `강아지 간식`).
3. 상품 상세에서 수량을 정해 장바구니에 담습니다. 하트를 누르면 찜한 상품에 들어갑니다.
4. 장바구니에서 수량을 바꾸거나 고른 상품만 주문합니다. **할인 후 합계가 30,000원 이상이면 배송비 무료, 미만이면 3,000원**입니다.
5. 주문서에 수령인 이름·연락처·주소를 넣고 **주문 완료**를 누릅니다. 검사를 통과하면 주문 번호(`O001` 부터)가 붙고 주문 완료 화면으로 갑니다.
6. 계정 메뉴 **Orders** → 주문 상세에서 주문 내용을 다시 보고 주문을 취소할 수 있습니다.

### 돌봄 예약

1. **PET SITTER → Find a Sitter** 에서 이름·활동 지역·돌봄 가능 동물·제공 서비스로 찾고 정렬합니다. 평균 평점 4.5 이상은 ‘우수 펫시터’ 입니다.
2. 펫시터 상세에서 요일별 이용 가능 시간과 서비스 요금을 보고 **예약하기**를 누릅니다.
3. 예약서에서 서비스·날짜(내일부터 30일 뒤까지)·시작 시각·수량과 반려동물 정보를 넣습니다. 끝나는 시각과 예상 금액이 바로 보입니다.
4. **예약하기**를 누르면 이용 가능 시간과 겹치는 예약을 검사한 뒤 예약 번호를 붙여 저장하고 예약 완료 화면으로 갑니다.
5. 계정 메뉴 **Reservations** → 예약 상세에서, 시작일이 오늘보다 뒤인 예약을 취소할 수 있습니다.
6. 이용이 끝난 예약(종료일이 오늘보다 이전)은 **후기 쓰기**로 후기를 남깁니다.

| 서비스 | 1단위 | 받는 동물 | 예약할 수 있는 시간 |
| --- | --- | --- | --- |
| 산책 · 방문 돌봄 | 1시간 | 산책은 강아지, 방문 돌봄은 강아지·고양이 | 시작~끝이 그날 이용 시간 안 |
| 데이케어 | 1일(9시간) | 강아지 | 시작~끝이 그날 이용 시간 안, 1일 단위 |
| 장기 돌봄 | 1박(24시간) | 강아지·고양이 | 맡기는 시각은 맡기는 날, 찾는 시각은 찾는 날의 이용 시간 안 |

### 그 밖의 화면

- **PROMOTION** → 기획전 목록 → 상세에서 묶인 상품을 봅니다.
- 오른쪽 아래 추천 도우미 버튼 → 문장으로 묻습니다. 창을 닫았다 열어도 대화가 이어지고, 새로고침하면 처음부터 시작합니다.
- **SUPPORT** → 공지 · FAQ · 1:1 문의. 상품 상세 문의 탭의 **1:1 문의하기**는 그 상품을 연결한 문의로 이어집니다.
- 계정 메뉴 **My Page** → **수정**을 눌러 내 정보·반려동물 정보를 고치고 저장합니다.
- 홈의 혜택 안내 팝업은 **오늘 하루 보지 않기**를 고르면 그날 자정까지 닫힌 채로 있습니다.

## 데이터 관리

### 기초 데이터 — JS 배열 import

`src/mocks/` 의 JS 파일 15개를 named import 해서 씁니다. 빌드 결과에 함께 들어가므로 따로 올릴 데이터 파일은 없습니다.

| 데이터 | 건수 |
| --- | --- |
| 상품 | 480(7분류) — 무한 스크롤 한 묶음 12개 × 40 |
| 펫시터 · 돌봄 서비스 | 40(8지역) · 4 |
| 펫시터 후기 · 상품 리뷰 | 78 · 156 |
| 기획전 · FAQ · 공지 | 3 · 27 · 12 |

앱이 처음 뜰 때 `src/utils/mockCheck.js` 가 기초 데이터를 한 번 검사합니다. 어긋난 곳이 있으면 담기·주문·예약을 멈추고
‘기초 데이터에 오류가 있어 구매·예약을 진행할 수 없습니다.’ 를 보여 줍니다.

### 운영 데이터 — localStorage 한 키

장바구니·주문·예약·후기·문의·찜·상품 리뷰·내 정보·홈 팝업의 ‘오늘 하루 보지 않기’ 를
localStorage 의 **`pettopia.store.v1`** 한 키에 JSON 하나로 저장합니다.

```
{ version, profile, cartItems, orders, reservations, reviews,
  inquiries, wishlistProductIds, productReviews, promotionHiddenUntil }
```

- 저장에 성공한 뒤에만 화면이 바뀝니다. 실패하면 화면은 그대로 두고 안내를 보여 줍니다.
- 주문 완료는 배송 정보 검사를 통과한 주문이 주문 내역에 저장된 상태, 예약 완료는 이용 가능 시간 검사를 통과한 예약이 예약 내역에 저장된 상태입니다.
- 저장 데이터는 접속한 브라우저와 주소마다 따로입니다. 개발 서버·preview·배포 주소는 서로 다른 저장 공간을 씁니다.
- 앱을 열 때 저장값을 검사합니다. 읽지 못하면 자동으로 지우지 않고 ‘저장 데이터를 불러오지 못했습니다.’ 와 **저장 데이터 초기화** 버튼을 보여 줍니다.
- 처음 상태로 돌리려면 개발자 도구 → Application → Local storage 에서 `pettopia.store.v1` 키만 지우고 새로고침합니다.
장바구니·주문·예약·후기·문의·찜·상품 리뷰·내 정보가 모두 지워지므로 초기화하려는 경우에만 합니다.

## 배포 방법

로컬에서 빌드한 `dist` 를 Cloudflare Pages 에 직접 올립니다. Git 연결이나 배포 명령 도구는 쓰지 않습니다.

**처음 배포**

```
npm run build → npm run preview 로 확인 → Ctrl+C
→ Cloudflare 대시보드 Build → Compute → Create application
→ (아래쪽) Continue to Pages → Drag and drop your files → Get started
→ 프로젝트 이름 입력 → Create project
→ code/dist 폴더 전체 업로드 → Deploy site
```

**수정 후 다시 배포**

```
소스 수정 → npm run build → npm run preview 확인
→ Compute → 기존 Pages 프로젝트 → Create deployment
→ Production → 새 dist 전체 업로드 → Save and deploy
```

- 기존 프로젝트에 **Production** 으로 올려야 대표 주소([https://pettopia.pages.dev)가](https://pettopia.pages.xn--dev)-eh3p/) 바뀝니다.
- 매번 **`dist` 전체**를 올립니다. 빌드할 때마다 JS·CSS 파일 이름이 내용에 따라 바뀌기 때문입니다.
ZIP 으로 올린다면 `dist` **안의 내용**을 압축해 최상위에 `index.html` 이 오게 합니다.
- `404.html` 을 만들지 않습니다. 없으면 Pages 가 SPA 로 보고 `/products/P001` 같은 주소도 앱이 처리합니다.
- 배포 뒤에는 배포 주소에서 상세 주소 직접 입력·새로고침, 구매·예약 흐름, 새로고침 뒤 저장 유지를 확인합니다.

## 적용한 리액트 개념

화면은 `src/pages/`(29개), 여러 화면이 함께 쓰는 부품은 `src/components/`(25개), 공통 틀과 공유 상태는 `src/Layout.jsx`, 계산·저장·검사 함수는 `src/utils/` 에 있습니다.

| 개념 | 적용한 곳 |
| --- | --- |
| 컴포넌트 분리·props | `ProductCard` · `SitterCard` · `EmptyState` · `FormField` · `QuantityInput` · `InfiniteList` · `Pagination` 등 공통 부품을 props 로 여러 화면에서 씁니다 |
| state · 이벤트 | `useState` 로 검색어·필터·정렬·폼 입력·확인 영역을 관리하고, 담기·찜·수량 변경·삭제·제출을 `handle…` 함수로 처리합니다 |
| 리스트·조건부 렌더링 | 상품·펫시터·주문·예약 목록을 `map` 과 고유 `key` 로 그리고, 빈 상태·오류·찾지 못함 안내를 조건에 따라 보여 줍니다 |
| 폼 처리 | 제어 입력과 제출 때 검사 — 주문서·예약서·1:1 문의·후기·상품 리뷰·마이페이지 |
| 라우팅 | react-router-dom 7 — `Layout` + `Outlet` 중첩 라우트, `useParams`(상세 화면), `Link`·`NavLink`, `useNavigate`(주문·예약 뒤 이동) |
| 공유 상태 | `Layout` 이 저장 데이터와 변경 함수를 가지고 `useOutletContext` 로 화면에 넘깁니다 |
| 효과·참조 | `useEffect` — 무한 스크롤(`IntersectionObserver`)·슬라이드 자동 전환 / `useRef` — 검색 창·팝업 `<dialog>`, 가로 목록 |
| 사용자 지정 | `useLocation`·`useLayoutEffect`(경로가 바뀌면 맨 위로) · `useId`(입력 id 중복 방지) · `useSearchParams`(1:1 문의의 상품 연결 한 곳) |

**해결한 문제**

| 증상 | 원인 | 수정 | 재확인 |
| --- | --- | --- | --- |
| 장기 돌봄을 어느 펫시터에게도 예약할 수 없었다 | 1박은 늘 다음 날 끝나는데 ‘하루 안에서 끝나는가’ 로 검사했다 | 맡기는 시각은 맡기는 날, 찾는 시각은 찾는 날의 이용 시간 안인지 본다 | 2박 예약은 저장되고, 찾는 날이 휴무인 1박은 안내와 함께 막힌다 |
| 스크롤하면 헤더가 사라지고, 다른 화면으로 가도 이전 스크롤 위치가 남았다 | 헤더가 화면과 함께 올라가고, 화면을 옮겨도 스크롤을 되돌리지 않았다 | 헤더를 위에 고정하고, 경로가 바뀌면 맨 위로 옮긴다 | 화면을 옮기면 맨 위에서 시작하고, 스크롤 중에도 헤더가 보인다 |
| 추천 도우미에 주문·예약 취소를 물으면 엉뚱한 FAQ 가 나왔다 | FAQ 에 취소 안내가 없었다 | 주문 취소·예약 취소 FAQ 를 더했다 | 취소 질문 두 개를 포함한 테스트 10건 모두 통과 |

**미구현·제한 사항**

- 모바일 화면 전체 대응은 범위에서 뺐습니다(데스크톱 기준). 상품 상세는 600px 폭에서 가로로 넘칩니다.
- 추천 도우미는 낱말 사전과 점수로 기초 데이터를 찾는 규칙 기반 검색입니다. 상품 가격 조건은 정가, 펫시터 요금은 서비스 1단위 기준으로 봅니다.
- 첫 접속이 무겁습니다 — 탭 아이콘 SVG 774KB, 배너·기획전 PNG 7장이 약 12MB 입니다.
